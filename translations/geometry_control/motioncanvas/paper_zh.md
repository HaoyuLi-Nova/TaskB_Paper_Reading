## 摘要

本文提出一种方法，让用户在图像到视频（I2V）生成中设计电影镜头。镜头设计是电影制作的关键环节，需要细致规划场景中的相机运动与物体运动。

在现代 I2V 系统中实现直观镜头设计有两个主要挑战：第一，有效捕捉用户的运动设计意图，相机运动与场景空间中的物体运动必须联合指定；第二，把运动信息表示成视频扩散模型能有效使用的条件，以合成图像动画。

为此我们提出 **MotionCanvas**：把用户驱动的控制接入 I2V 生成模型，使人能以场景感知方式同时控制物体与相机运动。通过连接经典计算机图形学与当代视频生成技术，我们证明可以在 I2V 合成中实现 3D-aware 运动控制，而无需昂贵的 3D 相关训练数据。MotionCanvas 让用户直观描绘场景空间中的运动意图，再将其翻译成视频扩散模型的时空运动条件信号。我们在广泛的真实图像内容与镜头设计场景上验证了方法有效性，并展示其增强数字内容创作流程、适配多种图像与视频编辑应用的潜力。

## 1. 引言

图像动画，也称图像到视频生成（I2V），使电影人与内容创作者能用动态运动把静图“带活”。该方向多年来吸引大量研究，探索过多种写实动画方法。近期视频生成模型显著改变了 I2V 合成，用生成技术从文本产出视频，打开新的创作可能。然而，动态内容创作本质由用户意图驱动：纯文本难以捕捉运动的精细细节，导致动画不确定、缺少控制。纯 I2V 的局限因此变得清晰。

在内容创作与电影制作中，镜头的运动设计至关重要：规划相机运动与物体运动，以构成连贯视觉叙事。例如，从图 1 最左列的同一张输入图出发，不同用户可能想探索不同相机运动（保持静止、dolly 后退、边环绕边升高）与物体安排（让男孩或风筝沿特定方向移动），以表达成片的创作构想。当前视频生成模型主要靠文本做运动控制，精度与表现力受限。近期工作尝试把相机与物体运动控制接入视频扩散模型，但仍无法充分处理二者纠缠，因而难以解释歧义的用户意图。例如用户拖拽角色手臂，可能意味着平移相机、移动角色，或只动手臂。

本文旨在让用户精确控制相机运动、物体全局运动（例如移动角色）与物体局部运动（例如移动手臂）。标准做法是准备带全部标签（相机外参、物体运动等）的视频训练数据。但这需要费力且可能不可靠的标注，最终限制训练数据的多样性与规模。我们改为用不依赖这类昂贵标签的运动表示：简单的 2D bounding box 与 2D 点轨迹，可自动、可靠地估计。这样几乎任何视频都能用于训练，生成多样性也更丰富。

仍有一个主要挑战：用户倾向于在 3D 场景空间中思考与规划运动，而视频生成模型用 2D 屏幕空间运动条件训练；用户又必须在 2D 图像画布上指定运动计划。换言之，需要把场景空间中的用户运动设计有效翻译成 2D 屏幕空间的控制信号（bounding box 与点轨迹）。受计算机图形学中经典场景建模启发，我们提出 **Motion Signal Translation** 模块：让用户在 3D 场景空间规划运动，再准确解释用户意图。该模块把用户运动分解为层次变换，并在把解释后的 2D 控制信号送入视频生成模型之前，纠正可能错误的用户输入。

我们将这套精简的视频合成系统命名为 **MotionCanvas**，在镜头设计与视频合成过程中以场景感知方式联合操控相机与物体运动。如图 1 所示，方法允许用户在固定期望相机路径的同时生成不同物体运动的镜头（注意每列结果中相机运动一致），反之亦然。MotionCanvas 在推理时用专门的 Motion Signal Translation 模块，把高层用户运动设计接到驱动视频扩散模型的屏幕空间控制信号。为此我们设计专门的运动条件化机制，引导基于 DiT 的视频扩散模型跟随捕捉相机与物体运动的控制信号。

贡献如下：

- 把电影镜头设计引入 I2V 合成过程。
- 提出 MotionCanvas，一套面向电影镜头设计的精简视频合成系统，提供整体运动控制，以场景感知方式联合操控相机与物体运动。
- 设计专门的运动条件化机制，用捕捉相机与物体运动的控制信号引导 DiT 视频扩散模型；并配合 Motion Signal Translation 模块，把描绘的场景空间运动意图翻译成屏幕空间条件信号。
- 在多样化真实照片上的评估确认 MotionCanvas 对电影镜头设计有效，并展示其用于多种创意应用的潜力。

## 2. 相关工作

**图像动画。** 早期工作大量借鉴经典图形学，通常试图从单张 2D 图重建 3D 几何再在新视角重渲染。*Journey into the Picture* 建立了提取平面层并合成最小 3D 场景的管线；3D Ken Burns 利用估计深度产生可信相机视差，SynSin 进一步改进。这些方法本质上只能在静照上生成相机效果，没有物体运动。

在相机运动之外，另一路工作只动画图像的选定部分，一般称为 cinematographs：按主体类别手工定义不同类型运动。更近的工作用深度网络预测运动以生成 cinemagraph。这些方法通常只能为云、烟等特定元素生成细微运动。

![图 2. MotionCanvas 总览。给定输入图像与高层场景空间运动意图，MotionCanvas 用 Motion Signal Translation 模块，借助基于深度的合成与层次变换，把运动（相机与物体运动及其时序）分解并翻译到屏幕空间。这些屏幕空间运动信号再送入视频生成模型，产出最终电影镜头。](../../../arxiv/geometry_control/motioncanvas/extracted/Graphics/Overview.png)

**图像到视频生成。** 视频基础模型近年进展显著，能从单图与用户文本提示生成高度写实的视频。但它们通常对生成视频中的运动提供有限或没有用户控制，从而限制适用性。

**可控视频生成。** 现有工作通常提供以下三种用户引导控制之一：

**(1) Bounding Box 控制。** 用户从物体位置开始画一串 bounding box 来控制物体运动。这些工作不提供相机运动可控性，单独用 bbox 不可避免引入歧义：不清楚该移动物体还是整幅场景去跟随 bbox。

**(2) 点轨迹控制。** 这些方法用点轨迹提供不错的拖拽式运动控制，但未能以 3D-aware 方式处理物体运动，且往往只支持有限条轨迹。

**(3) 相机控制。** 用显式 3D 相机参数在视频生成中提供相机运动控制。其训练数据大多限于静态场景与精选领域，因此只能产生很少物体运动，泛化不足。

相对地，我们的方法在统一框架中同时提供物体级控制（via bounding box 或点轨迹）与相机级控制。先前方法都未整合场景感知的物体控制，原因是缺少 3D 训练数据。我们仅用 2D 信号（例如点轨迹）训练，并用基于深度的合成实现 3D-aware 控制。

## 3. MotionCanvas

本方法把静图做成短视频，反映用户的运动设计意图。如图 2，MotionCanvas 包含三个主要组件：(1) 运动设计模块，捕捉多样化的场景感知运动意图；(2) 翻译模块，把这些意图转成屏幕空间运动信号；(3) 运动条件化的视频生成模型。

### 3.1 运动设计模块：捕捉用户意图

我们把输入图像当作运动设计画布，建立运动设计所锚定的起始场景。该设定使运动设计具有 3D 场景感知，捕捉物体、相机与场景之间的空间关系。统一界面分别控制相机运动、物体全局与局部运动，以及它们的时序。

**用 3D 相机路径控制相机运动。** 我们用标准针孔相机参数定义相机运动，把 3D 相机路径指定为每帧 $l$ 的外参 $E_l$ 与内参 $K_l$ 序列：$(E_l,K_l)_{l=1}^{L}$，其中 $E_l\in\mathbb{R}^{3\times 4}$，$K_l\in\mathbb{R}^{3\times 3}$。设计相机路径时，用户可指定关键时刻的相机姿态（相对初始视角的平移向量与旋转角），完整路径由插值得到。为更直观，系统还允许用户指定并混合 $M$ 种基础运动模式（例如 panning、dolly）以及对应方向与速度，再把这些模式转成 3D 相机路径（见附录）。

**用场景锚定 bounding box 控制物体全局运动。** 控制物体在场景中移向何处，对镜头设计至关重要。我们认为这种全局物体控制应以场景感知方式定义：物体定位锚定到底层 3D 场景中的位置。为此，我们通过最少指定起始与结束框、以及（可选）中间关键框，在输入图像上实现场景锚定的 bbox 放置。把 bbox 锚定到输入图像确立的固定视角，用户不仅能调位置，还能调框的尺度与形状，以描绘想象中的目标位置。这种场景感知 bbox 放置对物体位置、尺度、姿态以及相对相机距离提供直观控制。根据所给关键位置与输出视频预期时长，我们用 Catmull-Rom 样条插值生成平滑框轨迹。

**用点跟踪控制物体局部运动。** 全局物体运动定义物体如何在场景中改变位置，是镜头设计的主焦点；局部物体运动——描绘物体在位运动（例如举手、转头）——也能用细节与真实感丰富镜头。受近期拖拽式编辑成功启发，我们用稀疏点轨迹描绘局部运动。局部运动常涉及复杂几何关系与形变，稀疏点轨迹提供灵活的定义与操控方式。

**时序控制。** 物体与相机运动的时序控制使设计可协调，增强叙事流畅与视觉连贯。系统允许用户直接沿运动轨迹分配时间线。

### 3.2 Motion Signal Translation 模块

运动意图最适合在 3D-aware、以场景为中心的方式下设计，而视频生成模型往往最有效地用 2D 屏幕空间、以帧为中心、经视角相关投影后混合所有运动类型的数据来做运动条件化。这一落差来自：在大规模一般视频上提取可靠 3D 信息（相机运动、3D 物体跟踪）极具挑战。为应对该挑战，我们不追求让视频生成模型直接处理场景空间运动信息，关键想法是：把第 3.1 节得到的场景空间运动设计，翻译成可从 in-the-wild 视频可靠提取的、时空锚定的屏幕空间运动信号。

**用点跟踪表示相机运动。** 我们寻找一种屏幕空间运动信号，它 (1) 能从一般视频稳健提取，(2) 编码整段视频中相机运动的细节。人类视觉感知研究表明：把稀疏场景点跟踪投影到像平面，可可靠恢复自我中心运动。该洞察已广泛用于相机位姿估计与 SLAM。受此启发，我们用点跟踪表示相机运动。注意该信息可从真实视频稳健提取。

推理时，我们把 3D 相机路径转成 2D 点轨迹：在输入图像上随机采样一组点。为聚焦更好反映相机运动的静态背景点，我们用 YOLOv11 生成的 mask 排除可能运动的物体区域。再用现成单目深度估计器得到相机内参与深度图。最后根据 3D 相机路径与深度对这些点做 warp，得到对应的 2D 屏幕空间轨迹。

**用 bounding box 轨迹表示场景感知物体运动。** 用户定义的场景空间 bbox 轨迹反映运动意图，但投影到屏幕时会被相机运动与透视扭曲。我们要把这种场景锚定的物体 bbox 转到屏幕空间，使其类似于从真实视频提取的物体 bbox 序列。我们先用相机位姿与深度把场景空间 bbox 提升到 2.5D，再持续重投影到各帧屏幕空间。初始 bbox 的深度取 SAM2 生成的语义 mask 内平均深度。后续 bbox 使用 (1) 场景中某点（例如地面）的参考深度，或 (2) 由透视一致性得到的深度（bbox 变大意味着朝相机靠近）。利用所赋深度与相机位姿变换，时刻 $l$ 的 2.5D bbox $b_{\mathrm{scene}}^{l}$ 被投影到屏幕空间 $b_{\mathrm{screen}}^{l}$，位置与尺寸经过校准：

$$
b_{\mathrm{screen}}^{l}=\mathcal{T}_{\mathrm{camera}}^{l}(b_{\mathrm{scene}}^{l}),
$$

其中 $\mathcal{T}_{\mathrm{camera}}^{l}(\cdot)$ 表示相机运动变换。

**用点轨迹分解表示物体局部运动。** 我们用场景锚定的点轨迹描绘物体局部运动，重点是把每个场景锚定控制点 $p_{\mathrm{scene}}^{l}$（用先前算出的对应物体 bbox 深度把控制点提升到场景空间）转到对应屏幕空间 $p_{\mathrm{screen}}^{l}$。这要同时考虑相机与全局运动：

$$
p_{\mathrm{screen}}^{l}=\mathcal{T}_{\mathrm{camera}}^{l}\big(\mathcal{T}_{\mathrm{global}}^{l}(p_{\mathrm{scene}}^{l})\big),
$$

其中 $\mathcal{T}_{\mathrm{global}}^{l}(\cdot)$ 表示物体全局运动变换。假设局部运动相对全局运动的深度变化可忽略——局部运动常发生在相近深度平面上（例如挥手），这是合理假设——我们给所有局部运动点赋与初始位置相同的深度。这简化了基于相机运动的变换。

### 3.3 运动条件化的视频生成

视频扩散模型已成为视频生成的主导范式。我们在预训练的、基于 DiT 的 I2V 模型上构建运动条件化生成模型。该模型是内部开发的、把 DiT 适配到视频生成的标准变体，类似于现有开源适配。我们用屏幕空间运动条件微调，使其适配运动条件化生成问题。

![图 3. 运动条件化视频生成模型示意。输入图像与 bbox 彩色帧经 3D-VAE 编码器 tokenize 后相加。所得 token 与其他条件 token 拼接，送入基于 DiT 的视频生成模型。](../../../arxiv/geometry_control/motioncanvas/extracted/Graphics/MotionConditioning.png)

**点轨迹条件化。** 我们把 $N$ 条点轨迹各自编码成一组紧凑的离散余弦变换（DCT）系数。由于点跟踪时间频率低，长轨迹可压成 $K$ 个系数（实验中 $K=10$），其中 DC 分量编码初始位置，显式锚定轨迹起点。该紧凑表示 $C_{\mathrm{traj}}\in\mathbb{R}^{N\times K\times 2}$ 有两个优点：(1) 简化运动数据处理，灵活应对不同轨迹密度，并通过预计算提高效率；(2) 经 in-context conditioning 无缝接入 DiT。每条轨迹当作一个独立 token，其嵌入由 DCT 系数得到。

**Bbox 序列条件化。** Bounding box 传达复杂空间信息（位置、形状、姿态），并与轨迹分开注入，以区分相机运动与物体全局运动。我们先把 bbox 序列栅格化为独特的颜色编码 mask，形成 RGB 序列 $C_{\mathrm{bbox}}^{\mathrm{RGB}}\in\mathbb{R}^{L\times H\times W\times 3}$，再用基座 DiT 的同一预训练视频自编码器（3D-VAE）编码成时空嵌入 $C_{\mathrm{bbox}}\in\mathbb{R}^{L'\times H'\times W'\times C}$。这些嵌入被 patchify 成 token，加到带噪视频 latent token 上，如图 3。

**模型训练。** 由于采用潜空间扩散模型，所有 RGB 空间数据经 3D-VAE 编码器压成潜空间 token。运动条件化模型用 flow-matching 损失优化。记真值视频 latent 为 $X^{1}$、噪声为 $X^{0}\sim\mathcal{N}(0,1)$，时刻 $t$ 的带噪输入由线性插值产生 $X^{t}=tX^{1}+(1-t)X^{0}$。模型 $v_{\theta}$ 预测速度 $V^{t}=\frac{d}{dt}X^{t}=X^{1}-X^{0}$。训练目标为

$$
\min_{\theta}\mathbb{E}_{t,X^{0},X^{1}}\Big[\big\|V^{t}-v_{\theta}(X^{t},t\mid C_{\mathrm{img}},C_{\mathrm{traj}},C_{\mathrm{bbox}},C_{\mathrm{txt}})\big\|_{2}^{2}\Big],
$$

其中 $C_{\mathrm{img}}$、$C_{\mathrm{traj}}$、$C_{\mathrm{bbox}}$、$C_{\mathrm{txt}}$ 分别表示输入图像、点轨迹、bbox 与文本提示。我们仍保留文本条件，以便额外灵活控制视频内容变化。训练后，可在输入图像、文本提示与屏幕空间运动信号条件下生成干净视频 latent token $\hat{X}^{1}$，再解码回 RGB 帧。

### 3.4 用自回归生成可变长度视频

生成可变长度视频有利于电影叙事。我们通过自回归生成实现：比直接建模长视频更省算力，也反映复杂镜头常由短、简单镜头拼接而成。我们的 I2V 框架自然支持免训练的自回归长视频生成，但我们发现这常导致明显运动不连续，因为单张条件图像缺少足够的时间运动信息。为此我们训练 **MotionCanvas$_{\mathrm{AR}}$**，额外以短视频片段 $C_{\mathrm{vid}}$（16 帧）为条件。这种重叠短片段策略使每步生成以前一时空上下文为条件，过渡更自然。推理时模型以任意长度生成视频，每轮迭代有独立运动控制。为进一步精炼输入运动信号并与训练设定对齐，我们把用户意图与回溯运动结合，重算屏幕空间运动信号。该方法保证更平滑、更一致的运动生成（见附录）。

## 4. 应用

MotionCanvas 允许以场景感知方式灵活控制相机与物体运动。这支撑了我们的主应用——电影镜头设计框架，让用户交互管理镜头的关键运动方面。此外，运动表示的灵活性使其能自然用于多种简单的基于视频的编辑任务。

### 4.1 联合相机与物体控制的镜头设计

如图 4，框架能以场景感知方式精确、独立地控制物体与相机运动，在紧密跟随所给运动设计的同时，设计高度动态、视觉有吸引力的镜头。

图 4 中值得注意：两个例子里，每列结果遵循同一相机运动，而物体运动随对应指定的物体控制变化。通过以场景感知方式放置 bounding box，用户可实现多种场景空间效果。例如，底例中可使汽车在路上保持静止（第一行）、前进（第二行）或后退（第三行）。重要的是，这种场景锚定运动在相机运动独立变化时仍被保持。这凸显场景感知物体运动控制的重要性。

**带复杂轨迹的长视频。** 为生成包含复杂相机与物体运动的加长视频，框架采用“指定–生成”循环：用户为每段定义运动信号，再自回归生成视频块。受动画工作流启发，MotionCanvas 结合关键帧与插值以创造复杂运动路径。具体地，用户可为物体与相机运动设置关键帧，系统再在关键帧之间插值，得到平滑连贯轨迹。

如图 5，方法能生成带复杂相机运动控制序列的长视频。我们对每张输入图展示两个视频结果：相机控制相同（注意二者生成的相机运动几乎相同），同时有意控制不同物体运动。

### 4.2 物体局部运动控制

![图 6. 多样化、细粒度局部运动控制生成的视频（上），以及与相机运动控制协同（下）。原文为循环视频，此处引用首帧。](../../../arxiv/geometry_control/motioncanvas/extracted/Frames/app-local-motion/0.png)

MotionCanvas 也能控制物体局部运动，以潜在支持拖拽式编辑与生成。用户可在物体自身坐标中直接指定基于拖拽的轨迹来定义局部物体运动。这些点轨迹再被变换为合适的屏幕空间点轨迹，以条件化视频生成模型，同时考虑相机与物体全局运动。如图 6，方法能生成多样化、细粒度的局部运动，例如婴儿手臂的不同摆动方式。

此外，由于专门的运动翻译模块考虑局部运动与相机运动以及物体全局运动的协调，在不同相机与物体动态下仍能实现一致的物体局部运动控制（图 6 下）。这打开了把局部物体运动控制纳入上述镜头设计框架的可能。

### 4.3 额外应用：简单的基于视频的编辑

![图 7. 方法用于：（上）运动迁移；（下）视频编辑——更换、添加与删除物体。](../../../arxiv/geometry_control/motioncanvas/extracted/Graphics/additional_app.png)

**运动迁移。** 方法可适配为：把源视频的运动迁移到与起始帧结构相似的输入图像。借助通用的屏幕空间条件表示，框架有效捕捉并迁移物体与相机运动，即使涉及 3D 变换，也无需显式提取 3D 相机位姿。如图 7，苹果的旋转运动可迁移到狮子转头。

**视频编辑。** 运动迁移的概念可扩展到视频编辑：输入图像由首帧经图像编辑得到。利用通用屏幕空间条件表示，方法把提取的物体与相机运动传播到派生图像，保证一致、真实的动态。图 7 给出两例：在初始帧上做的编辑，用从原视频提取的运动信号传播，得到完整编辑后的视频。

## 5. 实验

### 5.1 实现细节

**数据。** 我们从内部数据集收集约 1.1M 高质量视频。用 DEVA 做全景分割并拟合 mask 以提取 bounding box。用 RAFT 光流链式计算稀疏点跟踪标注。为确保运动数据可靠，我们设定有效跟踪长度阈值。还根据 `vector`、`animation` 等关键词过滤一部分视频，以聚焦自然视频。Bounding box 进一步用相邻帧 IoU、尺寸变化比、位置变化（欧氏距离）以及关联物体是否属于运动物体列表等阈值精炼。最终得到约 600K 条运动质量好、标注保真度高的视频。训练时以 80% 概率随机选 $N$ 条点轨迹，其中 $N\sim\mathcal{U}(0,100)$；另有 10% 概率只从运动物体区域选点，10% 从非运动区域选点。

**模型。** 视频生成模块从预训练 I2V DiT 微调 100K 步，batch size 256，AdamW 学习率 $1\times 10^{-5}$、weight decay 0.1。训练主要使用 32 与 64 帧视频，采样 12 与 24 FPS，分辨率 $640\times 352$。推理时对文本条件使用 classifier-free guidance。

**表 1. 与 SOTA 方法在 RealEstate10K 测试集（1K）上的定量比较。$^*$ 表示零样本表现。**

| --- | --- | --- | --- | --- | --- |
| MotionCtrl | 0.8460 | 0.2567 | 1.2455 | 48.03 | 11.34 |
| CameraCtrl | 0.6355 | 0.2332 | 0.9532 | 39.46 | 13.14 |
| Ours$^*$ | **0.6334** | **0.2188** | **0.9453** | **34.09** | **7.60** |

### 5.4 联合相机与物体控制

我们做了用户研究（细节见附录），评估 3D 场景感知语境下联合相机与物体运动控制的感知质量。与拖拽式 I2V 方法 DragAnything、MOFA-Video 比较。现有方法都不是为 3D-aware 控制设计的，因此我们按它们的原始设定，直接把场景空间点轨迹作为基线输入。除用于物体局部运动控制的点轨迹外，我们还提供来自 bounding box 序列与基于深度 warp 的点轨迹，用于物体与相机的全局运动控制。参与者按运动遵循、运动质量与帧保真选择最佳结果。35 名参与者的统计见表 3。本方法在所有评估方面持续超过对手。视觉结果见图 10：两个基线都无法以 3D-aware 方式联合捕捉复杂物体全局运动（身体移动）、局部运动（放下手）与相机运动。相对地，MotionCanvas 跟随所有类型控制生成运动，得益于统一框架与运动表示设计。

### 5.5 消融实验

**相机运动表示。** 我们构造若干基线以考察相机运动表示的有效性：高斯图（对稀疏光流图做 2D 高斯模糊）、Plücker 嵌入，以及所提出的基于 DCT 系数的轨迹编码。定量比较见表 4。高斯图变体因固有歧义（尤其在更稠密控制下）在精确相机控制上较差，倾向于生成静止相机运动（高 FVD）。注意 Plücker 嵌入变体需要在带 3D 相机位姿标签的视频数据上训练（即 RealEstate10K 训练集）。它在该域内静态测试集上表现好，但无法生成物体运动（图 11 的猫），且缺少泛化。此外，我们的轨迹编码非常高效：只引入少量系数 token，却对相机内参与外参控制给出稳健表现。

**Bounding box 条件化。** 我们进一步评估 bounding-box 条件化。采用 Boximator 提出的替代设计：把 bounding-box 坐标拼接到视觉 token（Ours$_{\mathrm{coord}}$）。表 2 最后两列表明我们的时空颜色编码图条件化更优。欧氏坐标 token 与视觉 token 融合困难，导致 ObjMC 低。

| Plücker | **0.5965** | 0.2244 | **25.71** | 319.2 | 210s |

## 6. 结论

我们提出 MotionCanvas，一套统一的 I2V 合成系统，实现带灵活相机与物体运动控制的电影镜头设计。借助 Motion Signal Translation 模块，MotionCanvas 把直观的 3D 运动规划转成精确的 2D 控制信号，从而在不依赖 3D 标注的情况下训练视频模型，并拓宽训练数据来源。综合评估表明，MotionCanvas 能生成多样化、高质量、忠实反映用户运动意图的视频。

### A. 额外细节

MotionCanvas 用 16 个节点的 NVIDIA H100（80GB）训练（每节点 8 卡）。单张 H100 上，以 $352\times 640$、50 步去噪生成 32 帧片段约需 32 秒。训练时只优化 DiT transformer 块以及为 bounding box 条件化与 DCT 系数 tokenize 引入的额外 Linear/MLP 层，其余模块冻结。

### B. 用户界面

我们设计了示例用户界面，以灵活交互控制相机运动、物体全局与局部运动及其时序。界面示例见图 S1。

**指定相机运动。** 为便于定义相机运动轨迹，界面允许用户把 $M$ 种基础运动模式与可配置参数（方向正负、速度绝对值）组合，见图 S1 的 “Camera Motion Control” 面板。基础模式包括：水平 trucking 左/右、panning 左/右、dolly 进/出、垂直 pedestal 上/下、tilt 上/下、roll 顺/逆时针、zoom 进/出、orbit 左/右（可调半径）、circle 顺/逆时针、静止。每种模式所附数字的符号与绝对值定义相对首帧零姿态（即平移与旋转向量）的相机姿态。

**指定场景感知物体全局运动。** 交互画布（图 S1，“Object Global Motion Control”）上，用户可画起始与结束 bounding box，以及可选中间点。用 Catmull-Rom 样条插值得到平滑 bbox 轨迹。每个 bbox 可可选指定图像上的参考深度点。用户也可决定是否直接用该场景空间 bbox 序列作条件。利用场景空间 bbox 对创造 follow shot 或 dolly shot 等电影效果尤其有效。对标准场景感知物体全局运动控制，场景空间 bbox 按正文第 3.2 节赋深度，再用 Motion Signal Translation 转到屏幕空间。

**指定场景感知物体局部运动。** 专用画布（图 S1，“Object Local Motion Control”）上，用户可画任意数量点轨迹，按第 3.2 节赋深度。与 bbox 类似，这些点轨迹根据相机运动与物体全局运动变到屏幕空间。仅当轨迹起点落在物体语义区域内时，物体全局运动变换才生效。我们通过保持点相对底层 bounding box 的相对位置来变换物体局部运动点轨迹。界面还含 Preview Window，可预览生成视频以及场景空间与屏幕空间中的 bbox 序列和点轨迹。

受经典图形学成像启发，我们引入 Motion Signal Translation 模块，把场景空间中用户定义的运动意图转成屏幕空间运动信号，从而在 I2V 中以 3D-aware 方式联合控制相机与物体运动。该模块包含层次变换框架，以处理相机与物体运动的纠缠。为说明这些变换的有效性，我们给出视觉比较。

### F. 额外分析

**点轨迹密度对相机运动控制的影响。** 我们用不同数量 2D 点轨迹指定 orbit right 相机运动。低密度轨迹时运动欠指定、歧义大，生成的相机运动不跟随控制，倾向于 trucking left。提高密度后，生成运动能更好遵循 orbit 相机运动。可视化见项目页。

**文本提示的影响。** 全部实验使用简单文本描述。逐步更详细的文本提示表明：文本对相机运动控制影响不显著，但可生成如“下雨”“转身”等多样化动态。

### G. 局限性与未来工作

本工作提出用整体运动控制增强 I2V 的新框架，实现从单图做电影镜头设计。虽有实质进展，挑战仍在。

第一，视频合成模块使用视频扩散模型（VDM），虽能高质量生成，推理较慢（约 2 秒视频需约 35 秒）。该计算成本限制实时应用。探索更高效生成模型是有前景的方向。

第二，当前方法假设每个物体位于正对相机的平行深度平面上，以此近似物体局部运动。对多数自然场景有效，因为物体内深度变化相对到相机的距离通常很小；但这种伪 3D 近似可能不适合物体内深度变化显著的极端特写或微距镜头。未来可研究接入更显式的 3D 表述。

第三，系统目前不显式约束运动设计与文本提示的调和。一方面这提供灵活性，让用户联合使用两种模态探索创意变体；另一方面留下模态间运动信号冲突的可能。例如正文图 8 上行：文本提示表示猫在等待而非移动，而运动设计在视频后段显式控制猫前进时，运动会覆盖文本提示所暗示的运动。显式的运动感知 prompt 调和是有价值的延伸方向。
